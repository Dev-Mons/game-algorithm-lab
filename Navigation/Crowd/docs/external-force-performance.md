# 외력 사용 시 프레임 저하 분석 및 개선

## 확인한 원인

주요 병목은 시뮬레이션 CPU 계산이었다. 주황색 디버그 표시를 제거한 상태에서도 실제 10,000개체와 이동 원형 물체의 headless 스텝 P95가 53.85ms였다. CPU 샘플링에서도 외력 접촉 솔버, 공간 후보 조회와 계산 분할 계획이 큰 비중을 차지했다.

외력 하나가 전체 군중의 접촉 계산을 절대속도에 따라 최대 7회 반복하게 했다. 같은 방향으로 함께 이동하는 개체에도 이 비용이 적용됐다. 또한 미세한 접촉 충격까지 외력 상태를 전파하고, 실제 속도가 희망 속도와 거의 같아야 해제되는 조건 때문에 외력 상태가 계속 번졌다.

상태 전파 수정 직전, Open Field 1,000개체에 tick 30에서 중심 (235,360), 반경 100, 세기 400의 폭발을 한 번 적용하면 tick 420에도 945개체가 외력 상태였다. 수정 후 같은 재현에서는 tick 120에 0개체가 되었고, 활성 개체는 여전히 1,000개였다. 도착으로 개체 수를 줄여 얻은 개선이 아니다.

## 변경 사항

- 접근 중인 이웃의 상대속도로 시간 분할을 정한다. 일반 보행은 보수적인 속도 상한을 사용하고, 추가 공간 조회는 외력 대상과 이동 물체 주변에만 수행한다. 정적 벽 근처와 계획 조회 포화 시에는 기존 절대속도 기준으로 돌아간다.
- 평지는 12px 접촉 격자를 사용한다. 장애물 맵은 기존 개체 지름 크기의 격자를 유지해 밀집된 벽 주변에서 불필요한 후보가 한도를 소모하지 않게 했다. 후보 수·반복 상한·반경·속도·fixed dt를 개체 수별로 낮추지 않았다.
- 거리 제곱으로 비접촉 쌍을 먼저 제외하고, 접촉 가능성이 있는 쌍만 제곱근과 연속 충돌 계산을 수행한다. 장애물이 없는 이동과 정적 사각형의 이동 경로 밖 후보는 빠르게 제외한다.
- 예측된 벽 정지 속도를 접촉 반복에 반영해, 멈춘 선두에 뒤쪽 개체가 밀려 들어가는 문제를 방지한다.
- 보행 제어가 처리할 수 있는 작은 접촉은 실제 속도에는 반영하되 외력 상태를 전파하지 않는다. 보행 가속·회전·속도 제한으로 잔여 운동을 처리할 수 있으면 정상 이동으로 복귀한다. 별도 시간 만료나 속도 초기화로 운동량을 지우지 않는다. 제어가 꺼진 기준 장면은 약한 충격도 보존한다.
- Crowd Flow 속도 집계를 버퍼의 연속 메모리 순서로 순회하고, 비어 있는 방향 채널의 계산을 줄였다. 채널 합산 순서는 보존했다.

## 동일 조건 성능 비교

AMD Ryzen 9 9950X3D / Node v22.22.0. Open Field, seed 42, 반경 3.2, dt 1/60, 동일 밀도 확장, 예열 30 tick + 측정 90 tick, 3회 반복의 P95 중앙값. 이동 물체는 반경 18, 속도 240 px/s이며 실제 군중과 접촉한다. 품질 감사는 성능 실행에서 껐다.

| 실제 개체 수 | 변경 전 P95 | 변경 후 P95 | 감소 |
|---:|---:|---:|---:|
| 10,000 | 53.85ms | 22.02ms | 59.1% |

이번 변경 직전 재측정은 `external-optimization-before.json`에 보존했다. 해당 구버전 측정기는 소스 해시를 종료 시점에 읽었으므로 초기 편집이 포함된 해시이며, 실행 코드의 정확한 스냅샷으로 사용하지 않는다(파일에 주석 메타데이터 추가). 타이밍은 편집 전에 로드한 7-substep 코드의 결과다. 새 측정기는 실행 시작 시 소스 해시를 고정한다. 이전 이슈 수락 baseline은 덮어쓰지 않았다.

## 브라우저에서 렌더링과 계산 분리

1440×960 headless Chromium, 실제 CanvasRenderer, 고정 스텝 한 번/RAF, 예열 30 + 측정 90회. 렌더링 열은 Canvas 명령 제출의 CPU 시간이며 GPU 완료 시간은 아니다. 프레임 간격은 화면 주기, 시뮬레이션, 렌더링, UI 처리를 포함한다. 단일 관측 실행으로 네이티브 디스플레이의 FPS를 보장하지 않는다.

## 검증과 남은 한계

- `npm run verify`: 타입 검사, 테스트 181개, 프로덕션 빌드 통과.
- 외력·실험 UI·기존 Crowd 브라우저 테스트 19개 통과.
- 새 회귀는 빠른 동일 방향 이동, 벽에 도달하는 군중, 떨어진 이동 물체, 혼합 크기의 무작위 충돌, 군중 전체의 외력 상태 종료, 제어를 끈 약한 충격 보존을 검사한다.
- 평지의 few/blast/global/proxy/overlap × 실제 1K/10K/20K에서 별도 공간 인덱스로 모든 개체의 주변 쌍을 10 tick마다 검사했다. 아래의 0은 검사한 tick의 결과이며 중간 substep 전체의 완전한 증명은 아니다.

| 실제 개체 수 | 5종 입력 최대 샘플 침투 | 벽 겹침 | 후보 포화 |
|---:|---:|---:|---:|
| 1,000 | 0.000px | 0 | 0 |
| 10,000 | 0.000px | 0 | 0 |
| 20,000 | 0.000px | 0 | 0 |

바위 협곡은 추가 제한이 남는다. 아래 수치는 감사 ON 실행이며 평지 성능 비교와 분리한다.

| 바위 협곡 + 이동 물체 | 스텝 P95 | 최대 샘플 침투 | 후보 포화 | 벽 겹침 |
|---:|---:|---:|---:|---:|
| 1,000 | 29.72ms | 0.256px | 0 | 0 |
| 10,000 | 128.06ms | 6.209px | 6 | 0 |

**바위 협곡 10K의 밀집 외력 장면은 접촉 품질 기준을 통과하지 못했다.** 해당 장면의 겹침·후보 포화와 CPU 비용은 남은 제한이며, 이번 변경을 모든 시나리오의 60FPS 또는 완전 비관통 달성으로 보고하지 않는다. 20K 평지 역시 현재 CPU 계산량 때문에 지속적인 60FPS를 보장하지 않는다.

## 재현

```powershell
npm run verify
npm run test:e2e -- tests/browser/external-influences.spec.ts tests/browser/algorithm-lab.spec.ts tests/browser/crowd.spec.ts
npm run measure:external -- --mode=proxy --agents=10000 --output=baselines/my-external-performance.json
npm run measure:external -- --mode=blast --agents=1000,10000,20000 --quality=on --repeats=1 --output=baselines/my-external-quality.json
npm run dev -- --host 127.0.0.1 --port 4274 --strictPort
# 별도 터미널
npx vite-node scripts/measure-external-browser.ts --modes=none,blast,proxy --output=baselines/my-external-browser.json
```

최종 headless 수치와 세부 pass 시간은 `baselines/external-optimized-*.json`, 브라우저 수치는 `external-optimized-browser.json`에 있다. 기존 입력·단위·지원 한도는 [외력 계약](external-forces.md)을 따른다.
