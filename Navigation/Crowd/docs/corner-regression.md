# 연속 코너 회귀 검증

`winding-corners`의 기본 1,000명·seed 42·반경 3.2·벽 여유 0.35·1/60초 고정 step을 사용한다.
실제 벽 끝인 `x=408, y>504`, `x=672, y<216`, `x=936, y>504`를 통과한 유닛 ID와
할당 목표 도착을 확인한다. 짧은 초기 이동이나 희망 속도만으로 성공을 판정하지 않는다.
최종 독립 감사 실행에서 B0/B1/R/Q/D 모두 실제 1,000명이 필요한 코너를 통과해 도착했다.
R/Q는 각각 110.50초와 115.17초가 필요했으므로 60초 전원 도착 결과로 표시하지 않는다.

## 수정 전 결과

[수정 전 원시 기록](../baselines/corners-before-1000.json)은 모든 프리셋을 3,600 tick,
시뮬레이션 60초까지 실행했다. 실제 생성 수는 모두 1,000명이고 사용 불가 슬롯은 0이다.
B1/D는 이미 전원이 완주했다. 영구 정체가 재현된 프리셋과 단순히 오래 이동하는
프리셋을 구분해야 한다.

| 프리셋 | 60초 도착 | 첫째 / 둘째 / 셋째 필수 통과 | 최종 저속 지속 유닛 | 표본 최대 원판 침투 |
|---|---:|---|---:|---:|
| Legacy | 998/1,000 | 1,000/1,000 · 1,000/1,000 · 1,000/1,000 | 2 | 0.598084 |
| B0 | 998/1,000 | 999/1,000 · 998/1,000 · 998/1,000 | 2 | 0.029366 |
| B1 | 1,000/1,000 | 1,000/1,000 · 1,000/1,000 · 1,000/1,000 | 0 | 0.002028 |
| R | 814/1,000 | 999/1,000 · 997/1,000 · 664/687 | 54 | 0.019881 |
| Q | 825/1,000 | 999/1,000 · 998/1,000 · 670/687 | 88 | 0.003108 |
| D | 1,000/1,000 | 1,000/1,000 · 1,000/1,000 · 1,000/1,000 | 0 | 0.004788 |

모든 tick의 런타임 벽 겹침·정적 내부 시작과 프리셋별 120회 독립 감사의 벽 겹침은 0이었다.
표본에서 검출된 공개 상태 선분의 유닛 교차도 0이었다. 위 표의 잔여 원판 침투는 별도로
존재하므로 완전한 무겹침 보장을 의미하지 않는다.

## 확인된 원인과 수정 범위

- 코너 waypoint를 거리만 보고 건너뛰면 다음 선분이 벽을 가로질러 경로 희망 속도가 0이 될 수 있었다.
  실제 다음 선분이 보일 때만 전환하며, 도착·최종 감속에도 장애물 가시성을 반영한다.
- 접촉 순간의 유닛 간 CCD가 접선 이동까지 정지시키는 경우와, 허용된 극미한 벽 내부 오차에서
  음수 충돌시각 검사가 벽을 놓치는 경우가 있었다. 접촉 법선 성분과 접선 이동을 분리하고,
  수치 오차 범위만 명시적으로 정리한다. 실제 내부 스폰·점유 건설을 임의 이동시키지 않는다.
- 보존 슬롯의 간격은 원판이 겹치지 않는 조건뿐 아니라 지역 우회 경로의 여유와 도착 허용 오차까지
  수용해야 한다. 할당기와 지역 우회기가 같은 기하 계약을 사용하고 간격 변경 시 이전 슬롯을 재사용하지 않는다.
- 주차한 유닛을 우회할 때 최종 슬롯이 벽 뒤에 있으면 지역 그래프도 그 벽을 넘지 못한다.
  실제로 보이는 A* waypoint를 지역 우회 목표로 전달하며, 필요한 우회 꼭짓점을 단순 근접만으로 버리지 않는다.
- 저속 지속 시간만으로 정체를 모두 찾을 수 없었다. 마지막 유닛이 약 10의 속도로 움직이면서도
  30초 이상 같은 구간을 왕복한 사례가 있어, 전원 도착 조건을 유지한 1,000명 회귀 검증을 추가했다.
- Q의 양보 방향이 지역 우회 계산에 덮어써지는 경우를 고쳤다. 실제 지역 경로를 선택한 뒤
  일관된 회전 방향으로 양보를 적용해, 마주 오는 두 유닛이 서로 다른 쪽으로 비켜가게 한다.
  두 이동 유닛과 두 고정 유닛으로 축소한 실제 실패 사례에서 도착을 검증한다.
- 정체한 이동 유닛끼리는 ID 우선순위에 따라 한쪽이 우회 경로를 찾는다. 실제 활성 상태·
  반경·통로 잠금과 ORCA·CCD·PBD의 몸체 검사는 유지한다. 주차 유닛이 원래 A* waypoint를
  차지한 경우 실제 다음 경로 점으로 재연결하며 모든 연결 간선의 정적 여유를 검사한다.
- 벽 옆의 유효한 시작점이 보수적인 우회 다각형 내부에 놓일 때, 다각형 꼭짓점만으로는 진입
  경로를 찾지 못했다. 시작·목표 좌표의 축과 우회 원의 실제 교점을 추가하고 동일한 여유 검사를 적용한다.

Legacy의 남은 2명은 세 코너를 모두 통과했으나 출구 반경 58보다 약 `2e-12` 바깥에서
속도가 0으로 수렴했다. 기존 비교 기준의 숫자 동작은 보존한다.

## 목표 모델과 통과 수 해석

R/Q의 명령 중심은 곧 모든 유닛의 최종 점이 아니다. 실제 보존 슬롯을 할당하며, 일부 슬롯은
셋째 벽 앞의 열린 영역에 있다. 수정 전에는 313개, 간격 계약 수정 후에는 283개가 셋째 선
이전에 있었다. 따라서 셋째 필수 통과 분모는 각각 687명과 717명이다. 이 분모와 실제 할당
목표 도착을 함께 검증한다. 일부 유닛의 추가 왕복 통과를 전원 완주로 해석하지 않는다.
UI는 실제 슬롯과 명령 중심을 구분해 표시한다.

B0/B1/D 및 Legacy는 세 벽 이후의 공통 출구를 사용하므로 전원에게 세 번의 통과가 필요하다.
이 장면에는 솔버용 `routeGates`가 없다. 진단의 세 선은 관측만 하며 예약 제약을 주입하지
않으므로 Q의 결과를 통로 배치 정책의 효과로 설명하지 않는다.

## 최종 검증 결과

[최종 원시 기록](../baselines/corners-fixed-1000.json)은 같은 기본 config·맵·seed로
각 프리셋을 최대 7,200 tick까지 실행하고 전원 도착하는 순간 종료했다. 실제 생성과 도착은
모두 1,000명이며 사용 불가 슬롯은 0이다. 다음은 시뮬레이션 시간이며 성능 순위나 FPS가 아니다.

매 tick 수치는 유한했고 런타임 벽 겹침과 정적 내부 시작의 최댓값은 모든 프리셋에서 0이었다.
독립 감사의 벽 겹침과 공개 상태 선분 교차 검출도 모두 0이었다. **잔여 원판 접촉은 0이 아니었다.**

선분 침투는 접촉한 상태에서 시작하는 경우도 포함한다. 따라서 이 값과 별도로 정의된
양 끝점이 분리된 유닛의 교차 검출 수를 혼동하지 않는다. 최대 끝점 침투 0.040913은
기본 지름 6.4의 약 0.64%이며, 유한 반복 접촉 보정이 완전한 무겹침을 보장하지 않음을 보여준다.
검증 범위는 기본 1,000명·seed 42의 이 장면이다. 다른 seed·과밀 설정·모든 맵에서의
전역 무교착 보장으로 확장하지 않는다. 진단·브라우저·다른 검사가 함께 실행됐으므로
기록된 벽시계 시간을 성능 비교나 렌더 FPS로 해석하지 않는다.

최종 실행 소스는 `baselines/corner-fixed-source`에 보존되어 있다. 전체 digest는
`0ef09f4ba784410164e267a13b4b9a849e395de807669c7d2d955f2c91b3ece1`이며,
실행 중 변경 파일은 없었다. 앞선 실패 기록의 결과를 이 최종 결과와 혼합하지 않는다.

## 재현 명령과 회귀 테스트

```powershell
# 수정 전 보존 소스. 현재 src 수정과 독립적으로 실행된다.
npx vite-node scripts/diagnose-corners.ts --source=baselines/corner-before-source --presets=legacy,B0,B1,R,Q,D --agents=1000 --ticks=3600 --audit-every=30 --output=baselines/corners-before-replay.json

# 최종 보존 소스: 최대 120초, 전원 도착하면 즉시 종료. 진행 중이면 60초 체크포인트도 남긴다.
npx vite-node scripts/diagnose-corners.ts --source=baselines/corner-fixed-source --presets=B0,B1,R,Q,D --agents=1000 --ticks=7200 --stop-on-complete=true --audit-every=30 --output=baselines/corners-fixed-replay.json

# 모든 프리셋 128명·60초 및 R/Q 기본 1천 명·최대 120초 회귀.
npx vitest run tests/behavior/lab-corners.test.ts
```

진단은 300 tick마다 진행·도착·저속 지속·사용 불가 슬롯·실제 통과 수를 저장한다.
가장 오래 멈춘 활성 유닛 12명과 아직 통과하지 못한 각 구간의 대표 유닛에 대해 위치·실제 속도·
희망 속도·목표·거리도 남긴다. 현재 러너의 `firstAllArrivedTick`은 실제 전원 도착 tick이며 미도착이면 `null`이다.
`--tail-ticks`와 `--tail-presets`를 사용하면 기본 구간 이후 특정 프리셋만 같은 실행 상태에서
명시한 상한까지 계속할 수 있다. 연장을 위해 처음부터 재실행하지 않는다.

모든 tick에서 유한 수치와 런타임 벽 상태를 검사한다. 독립 감사는 30 tick마다 및 최종 tick에
별도 공간 인덱스로 모든 후보를 검사하며, 공개된 두 상태 사이 선분만 관찰한다. 표본 사이 tick과
공개되지 않은 substep 곡선의 무충돌을 증명하지 않는다. JSON에는 전체 config·scenario·options,
소스별 SHA-256, 최종 state hash, 감사 범위·비용을 보존한다.

행동 테스트는 128명에서 모든 실험 프리셋의 실제 통과·전원 도착을 확인한다. 기본 1천 명에서만
나온 실패를 놓치지 않도록 R/Q 1,000명도 최대 7,200 tick 안에 전원이 도착해야 통과한다.
프리셋의 실제 할당 목표에 필요한 통과 수를 검증하며, 모든 tick의 최대 정적 내부 시작과 벽 겹침,
수치 유한성, 종료 시 독립 기하 검사를 확인한다. 전원 도착할 때만 조기 종료한다.

최종 자동 검증에서 **Vitest 24개 파일·208개 테스트가 통과**했고, **실제 브라우저 14개 테스트가
통과**했다. 브라우저 검증에는 R/Q 기본 1,000명 전원 도착과 프리셋 전환·리셋·간격 변경 시
슬롯 재할당이 포함된다. **형식 검사와 프로덕션 빌드도 통과해 `npm run verify`가 exit 0으로
완료**됐다. 긴 행동 테스트는 300 tick마다 이벤트 루프에 제어를 돌려줘 Vitest 보고 지연을
막는다. 최종 실행에는 RPC 오류가 없었으며, 유닛 이동 tick·조건·단언은 유지했다.

## 원시 증거와 보존 소스

실패한 기록도 원인 추적을 위해 보존한다. 파일명에 `verified`, `final`, `acceptance`가 있어도
그 이름 자체가 통과 판정을 뜻하지 않는다.

| 기록 | 의미 | 보존 소스 |
|---|---|---|
| [corners-before-1000.json](../baselines/corners-before-1000.json) | 수정 전 60초 기준 | `corner-before-source`, digest `d89eeeb5…c542` |
| [corners-after-1000.json](../baselines/corners-after-1000.json) | 접선 수정 중 벽 오차 회귀를 발견한 실패 기록 | `corner-after-source`, `e79dbf48…c766` |
| [corners-verified-1000.json](../baselines/corners-verified-1000.json), [tail](../baselines/corners-verified-tail-1000.json) | 벽 오차 해소 후에도 R/Q 120초에서 967/961명 | `corner-verified-source`, `33ed6c87…5698` |
| [corners-final-1000.json](../baselines/corners-final-1000.json) | 간격 계약 수정 후 R/Q 60초 885/853명 | `corner-final-source`, `d90d8239…6740` |
| [corners-acceptance-1000.json](../baselines/corners-acceptance-1000.json) | 실제 waypoint 전달 후에도 R/Q 120초 999/986명 | `corner-acceptance-source`, `fdccbbea…a291` |
| [corners-fixed-1000.json](../baselines/corners-fixed-1000.json) | **최종: 실험 프리셋 다섯 개 전원 도착·필수 코너 통과** | `corner-fixed-source`, `0ef09f4b…ece1` |

모든 소스 폴더는 `baselines/` 안에 있다. 수정 전 최초 실행의 Temp 복사본과 영구 보존본은
35개 TypeScript 파일의 SHA-256이 모두 일치한다. 전체 digest와 파일별 값은 각 JSON manifest에
들어 있다. 중간 소스는 실행 중 변경되지 않았으며, 최신 구현과 혼합해 성공 결과로 사용하지 않는다.
