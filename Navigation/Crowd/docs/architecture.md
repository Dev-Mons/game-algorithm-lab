# 구조와 알고리즘

현재 실행 코드의 책임과 수치 모델을 설명합니다. 이식 API는 [native-porting.md](native-porting.md),
개선·측정 절차는 [development.md](development.md)를 사용합니다.

## 계층과 소유권

```text
엔진 또는 웹 호스트: 입력 / 고정 tick 호출 / 좌표 변환 / 렌더링
  └─ CrowdKernel: 상태, 경로, 외력, 군중 이동, 충돌의 계산 순서
       ├─ FlowField: 정적 지형과 목표에 따른 경로 안내
       ├─ CrowdField → CrowdFlowSolver: 밀도·운동량 → 방향별 속도·압력
       └─ CrowdMovementSolver: 보행 제어 → 군중 접촉 → 정적 충돌

웹 실험실: CrowdSimulation extends CrowdKernel
  └─ 시드 배치 / 프리셋 교체 / 측정 / 기록 / Canvas 렌더링
```

`src/core/simulation.ts`는 기존 실험실 import의 호환 경로입니다. 계산 코어만 가져올 때는
`src/core/index.ts`에서 시작합니다. `tsconfig.core.json`이 DOM·Node 타입 없는 의존 경계를 검사합니다.
코어의 시계 hook은 기본 비활성이며 실험실 어댑터만 실제 시간을 측정합니다.

`AgentBuffer`는 x/y, vx/vy, pushVx/Vy, active, stalledFor, intentX/Y, heading을 별도 배열로 저장합니다.
vx/vy는 전체 속도, pushVx/Vy는 실제 외력·접촉에서 발생한 물리 속도 성분입니다.
코어가 위치·속도를 최종 결정하며, 렌더러는 `previousState`와 최신 `state`를 보간합니다.
엔진 물리가 같은 유닛을 다시 적분·밀어내면 원본과 다른 운동이 됩니다.

## 한 tick의 계산 순서

1. 이전 상태를 보존하고 도착자를 비활성화합니다.
2. 외력 입력을 소비해 물리 속도에 더합니다.
3. 실제 위치·속도를 CrowdField에 산포해 밀도와 운동량을 구성합니다.
4. 필요한 경로 필드를 갱신하고 각 유닛의 선호 이동 속도를 구합니다.
5. 방향별 격자 수송과 공유 밀도 압력을 풀어 이동 제안을 수정합니다.
6. 전방 회전과 보행 속력 증감을 독립적으로 제한하고, 기록된 밀림 속도를 더해 이동을 예측합니다.
7. 정적 벽 sweep으로 예측 이동을 자른 뒤 접촉 격자를 만듭니다.
8. swept-pair 이동 제한과 XPBD 겹침·마찰 보정을 수행하고, 최종 정적 sweep으로 검사합니다.
9. 속도를 반영하고 도착·지표를 계산한 뒤 current/next 버퍼를 교환합니다.

### 경로 안내

- 웹 실험실은 **공유 평행 방향장**(`parallelRouting=true`)과 기존 방향별 밀도·충돌 계산을 모든 지형에서 사용합니다.
  아래의 지형 연결 그래프를 재사용하되, 통과 구간의 특정 위치 대신 다음 영역으로 향하는 공통 진행 축을 계산합니다.
  직선에서는 평행하게 진행하고, 최대 6셀 앞의 회전 방향을 smoothstep으로 섞습니다. 선분 안전 검사를 통과하지 못하면
  미리 보는 거리를 줄이거나 기존 안전 격자 방향으로 복귀합니다. 객체별 좌우 위치나 분기 기억은 안내에 사용하지 않습니다.
  결과는 목표·지형 변경 시 반경별 격자에 캐시합니다. 실행 중에는 이 격자를 보간하고 현재 위치의 선분 안전을 확인하므로
  객체마다 통로 경로를 다시 따라가지 않습니다. 화면과 실제 경로 샘플이 같은 캐시를 사용합니다.
  `parallelRouting`은 코어·CLI에서 생략/false이면 기존 계산을 보존하고, true이면 과거 객체별 통로 안내보다 우선합니다.
  동적 비용 안내를 켜면 기존 동적 필드가 우선합니다.
  객체별 별도 분리·정렬·응집 단계는 없습니다. 군중 반응은 아래 격자 수송·압력 및 접촉 단계가 담당합니다.
  **공유 경로 방향**은 위치별 경로 샘플을 재구축 때 캐시하고, **개체 이동 의도**는 실제 보행 목표를 표시합니다.
  속도 표시는 회전 제한·접촉·외력까지 포함하므로 보행 목표와 다를 수 있습니다.
- 과거 비교용 `corridorRouting=true`는 `parallelRouting=false`인 코어·CLI에 남아 있습니다. 웹의 통로 토글과 `corridor` URL 선택은 제거했습니다.
  [corridor-field.ts](../src/algorithms/flow-field/corridor-field.ts)는 반경별로 셀 전체가 안전한 공간만 사용해
  장애물 경계의 가로·세로 분할선으로 직사각형 영역과 그 사이의 넓은 통과 구간(portal)을 만듭니다.
  영역 중심 간 거리로 역방향 Dijkstra를 계산하고, 각 영역은 비용이 낮은 다음 영역 하나를 선택합니다.
  거리 차이가 1e-7 이내인 동률 경로는 안전 격자의 정적 potential을 경로 길이에 대해 적분한 값이 낮은 쪽을 선택합니다.
  같은 점수는 영역 ID로 결정합니다. 비용이 감소하는 이웃만 선택해 순환을 막고 heap 탐색 순서 의존성을 제거합니다.
  객체는 초기 위치에서 진행 방향에 수직인 정규화 위치(0~1)를 얻고, 연속 구간에서도 그 좌우 순서를 유지합니다.
  좁은 구간에서는 폭을 줄이고 코너에서는 각자의 구간 위치로 회전합니다. 대형 객체는 별도 clearance 장을 사용합니다.
  코너 방향은 경계를 넘은 뒤 교체하지 않고, 경계까지의 법선 거리가 6개 경로 셀(기본 144px) 이내이면 다음 구간 방향을
  smoothstep으로 미리 섞습니다. 최대 8개 구간을 보며 경계에서는 다음 구간 방향의 가중치가 1이 됩니다.
  보정 방향이 벽을 가로지르면 회전 범위를 절반씩 줄이고, 마지막에는 기존 통과 구간 목표로 복귀합니다.
  샘플은 구간 목표까지의 실제 선분과 짧은 전방 구간을 검사하고, 불가능한 경우 기존 안전한 격자 방향으로 복귀합니다.
  보수적인 영역 셀 밖의 벽 주변 여백은 인접 3×3 셀 안에서 정확한 반경 선분 검사를 통과하는 가장 가까운 영역으로
  안내를 연장합니다. 따라서 실제로 걸을 수 있는 여백에 진입했다는 이유만으로 우회 경로가 바뀌지 않습니다.
  객체는 마지막 안내 영역도 기억합니다. 선택한 다음 영역으로 진입하면 즉시 진행하고, 다른 가지 쪽으로 밀렸을 때는
  이전 영역까지 안전하게 연결되고 거리가 반 셀 이내인 동안 기존 선택을 유지합니다. 더 멀리 밀리거나 연결이 막히면
  현재 위치에서 다시 선택합니다. 서로 다른 우회 경로의 방향을 평균하지 않습니다.
  목표 영역은 같은 통로가 선택한 출구를 사용합니다. 영역 전체와 목적지 seed를 감싸는 사각형에 반경 확장 장애물이 없는
  열린 공간에서는 통로 안내를 해제합니다. 실제 진입점까지의 직선도 clearance 검사를 통과해야 합니다.
  열린 합류 공간의 분할선은 필수 경유점이 아니지만, 코너 옆에서 일부 객체만 목표를 볼 수 있다는 이유로 폭 유지를 풀지는 않습니다.
  최종 영역 또는 목표가 보이는 도착 감속 범위에서도 직접 접근합니다.
  통로 모드의 점 도착은 거리 약 1e-9px의 수치 오차를 허용해 경계에서 무한 감속하는 상태를 방지합니다.
  초기화·목표·지형 변경은 통로와 객체별 좌우 위치를 다시 계산하고 기억한 안내 영역도 초기화합니다. 위치·속도를 직접 바꾸는 안내는 아닙니다.
  `dynamicRouting=true`에서는 기존 동적 비용 안내가 우선하며, 통로 방향은 적용하지 않습니다.
  디버그 Flow Field는 셀 위치에서 정한 좌우 위치의 방향을 캐시해 표시합니다. 실제 상·하 우회 분기 경계는 남으며,
  객체가 유지 중인 좌우 위치·안내 영역에 따른 방향은 위치만으로 표시하는 이 미리보기와 다를 수 있습니다.
  진입 경로가 하나인 코너에서는 진입·진출 구간의 좌우 좌표를 연결해 표시 방향도 경계에서 연속적으로 이어집니다.
  기존 `directionX/Y`·거리 필드는 안전 복귀와 동적 안내용으로 유지합니다.
- 같은 목표·반경 클래스는 FlowField를 공유합니다. 생성 그룹은 통계상 구분되어도 같은 목표면 같은 장을 씁니다.
- `goalRegions`를 지정하면 모든 생성 그룹이 반경 클래스별로 다중 출발 역방향 Dijkstra 필드를 공유합니다.
  최대 32개 사각형과 닿는 셀 중 실제 원형 clearance·구간 검사를 통과한 내부 지점을 출구 seed로 삼습니다.
  셀보다 작은 영역은 셀 중심에서 유효 내부 지점까지의 거리 비용을 포함합니다. 벽 셀을 출구라는 이유로 열지 않습니다.
  각 셀은 최소 비용으로 이어지는 seed를 보관합니다. 방향 보간에서는 다른 목적지로 향하는 화살표를 섞어
  서로 상쇄하지 않으며, 직선 접근도 선택된 영역과의 실제 충돌 검사를 통과해야 합니다.
  넓은 출구는 중심에 몰리지 않고 가까운 유효 가장자리로 진입합니다. 균등 배정이나 출구별 정원 정책은 없습니다.
- 기본 `dynamicRouting=false`: 목표나 지형 변경에만 경로를 다시 만듭니다. 밀집했다고 자동 우회하지 않습니다.
- `dynamicRouting=true`는 비교용 선택 기능입니다. 밀도·과부하·역방향 흐름 비용, 평활화와 방향 hysteresis를 적용합니다.
- 직선 목표 접근은 LOS와 clearance 검사를 통과해야 합니다. 경로 샘플 실패를 벽을 향한 직진으로 대체하지 않습니다.
- 기본 반경 이하와 큰 반경의 두 clearance 클래스를 사용합니다. 큰 유닛은 `maxAgentRadius` 기준의 보수적인 장을 공유합니다.
- `preserveBlockedGoal=true`이면 장애물로 막힌 목표 셀을 열지 않고 경로를 도달 불가능 상태로 둡니다. 기본값은 기존 참조 재생을 보존하는 false입니다.
- `routeGates`는 통과량을 재는 영역이며 이동을 지시하는 중간 목표가 아닙니다.
- 영역 목적지의 도착은 유닛 중심이 사각형에 포함되고 정적 clearance가 유효할 때입니다.
  `goalRadius`는 적용하지 않습니다. 영역 밖에서 감속만 하다가 멈추지 않도록 최소 접근 속도를 유지합니다.
  목표/지형 변경은 seed와 목적지 선택도 갱신하며, `setGoal()`은 영역을 해제하고 기존 한 점 방식으로 돌아갑니다.

### 밀도와 압력

각 유닛의 질량 가중치는 `(radius / agentRadius)²`입니다. 위치·운동량은 bilinear scatter와
보존적 blur를 거치고, 8개 heading channel에 인접한 두 방향의 가중치로 기여합니다.
반대 흐름을 하나의 평균 속도로 상쇄하지 않기 위한 구성입니다.

공유 압력은 목표 밀도 초과량과 예측 mass-flux divergence로 계산합니다. 셀 중심의 유한 반복
투영이며, 양의 압력만 사용합니다. 음의 압력·인력으로 내부 구멍을 채우는 모델은 아닙니다.
Gather는 희박한 구역의 경로 세부를 유지하며, 운동량 혼합과 구별되는 순수 압력 보정 속도도 제공합니다.
Gather의 보행 목표는 압력 보정 전의 운동량 혼합 결과이며, 압력의 앞뒤·옆 성분은 같은 tick에
하나의 밀림 속도 변화로 반영합니다. 앞뒤 성분만 보행 가감속을 거치거나, 같은 압력을 보행 목표와
밀림에 이중 적용하지 않습니다. 압력 보정은 속도 투영 결과이므로 추가 `dt`를 곱하지 않습니다.
실제 속도에 적용할 때 경로 방향 속도를 0 아래로 새로 내리지는 않습니다. 외력으로 이미 후진 중이라면
그 기존 후진은 유지할 수 있지만 압력이 더 강하게 역수송하지 않도록 제한합니다.
투영 결과의 속도 변화 상한은 `maxAcceleration × fixedDelta`입니다. 밀도 완화 시간은 목표 밀도 예측에만
사용하며 한 틱의 충격량 상한을 늘리지 않습니다. 따라서 같은 시간에 더 자주 계산한다고 압력 가속 예산이 커지지 않습니다.
압력으로 생기는 밀림 속력은 보행 상한과 기존 밀림 속력 중 큰 값으로 제한해 반복 투영의 무제한 가속을 막습니다.
이 제한으로 보행 속력을 다시 조절하거나 기존의 더 강한 외력을 즉시 제거하지 않습니다.

### 보행과 접촉

`turnSpeed`는 몸의 전방(`heading`, 화면의 흰 막대)과 보행 방향이 함께 회전하는 기본 속도입니다.
회전 목표는 군중 속도·압력 보정 전의 경로 방향(`intentX/Y`)입니다. 군중 보정 후 속도 벡터를
전방 목표로 사용하지 않으므로 밀집 군중의 운동량이 목표 각도를 뒤로 당기지 않습니다.
압력 보정 전 군중 혼합 속도의 경로 방향 성분은 보행 목표 속력에, 실제 압력과 외력·접촉은
아래의 밀림 성분에 반영합니다. 군중의 평균 이동 방향 자체를 밀림 힘으로 추가하지 않습니다.
웹 기본값인 **큰 각도에서 빠르게 회전**(`adaptiveTurning=true`)은 전방과 경로 사이의 최단 각도 차이 α에 따라
회전 속도를 높입니다. |α|≤30°이면 설정 속도의 1배, |α|≥120°이면 4배이며 그 사이는
`t=clamp((|α|-30°)/90°,0,1)`, `배율=1+3t²(3-2t)`로 부드럽게 연결합니다.
각도 차이가 작아지면 설정한 기본 속도까지 내려오며, 기본 속도보다 낮추지는 않습니다.
매 tick의 회전량은 남은 각도 차이로 제한해 목표 방향을 지나치지 않습니다. 설정 속도 0이면 회전하지 않습니다.
이 기능은 보행 속력을 감속하지 않으며 실행 중 경로 재구축·객체 재배치 없이 켜고 끌 수 있습니다.
코어의 생략/false 기본값에서는 `turnSpeed`가 고정 회전 상한이며 기존 재생을 보존합니다.
국소 회전 제어이므로 임의 지형에서 순환 탈출이나 도착을 보장하지는 않습니다.
일반 보행은 속력과 각도를 별도로 계산합니다. `maxAcceleration × dt`로 속력의 증가·감소만 제한한 뒤,
`turnSpeed × 배율 × dt` 이내로 회전한 전방에 그 속력을 적용합니다. 회전에 가속도 예산을 사용하지 않으므로
가속도가 작거나 0이어도 움직이던 유닛은 설정된 회전 속도로 방향을 바꿀 수 있습니다. 장애물 근처에 있다는 이유만으로
회전 제한을 해제하지 않으며, 일반 이동에서 0이면 전방은 고정됩니다.
실제 벽 충돌(월드 경계 포함)이나 정적 침투 보정이 발생한 tick에는 저장된 플로우 필드 방향으로
전방을 즉시 맞춥니다. 충돌로 보정된 위치와 속력은 유지하고 속도 방향도 정렬해 다음 tick부터
그 전방으로 이동합니다. 이 충돌 반응은 회전·가속도 제한의 예외이며, 경로 방향이 0이면 적용하지 않습니다.
기존 충돌 결과와 해당 tick의 경로 방향을 재사용하며 추가 경로 탐색이나 이동 sweep은 수행하지 않습니다.
경로·밀도에 따른 목표 속력 감소와 도착 처리는 유지됩니다. 모든 유닛은 외력 유무와 무관하게
`전방 × 보행 속력 + 밀림 속도` 한 식으로 이동합니다. 이전 보행 속력은 `length(v - pushV)`로 구하며,
전방과 실제 속도의 각도 차이로 이동 모드를 선택하지 않습니다. 외력 입력은 전체 속도와 pushV에
같은 Δv를 더합니다. 군중 압력의 전체 보정도 같은 밀림 성분에 더합니다. 실제 접촉 뒤에는 막힌
보행을 감속하고 남은 접촉 속도를 pushV에 기록합니다.
밀림의 전방 성분은 목표 속력에 이미 기여한 양으로 빼서 보행 가속을 중복하지 않습니다.
충돌 없는 이동에서는 위치 차분 오차를 밀림으로 기록하지 않습니다.
밀림은 매 tick `maxAcceleration × dt`만큼 크기를 줄이고 방향은 유지합니다. 이 복구는 전방 회전
예산을 사용하지 않으며, 가속도 0에서는 밀림이 유지됩니다. pushV가 0이면 보행은 항상 전방과
일치하고, 실제 밀림·충돌 보정 중에만 변위가 전방과 다를 수 있습니다. 도착·초기화는 pushV도 지웁니다.
개체 간 접촉이나 외력만으로 벽 충돌의 즉시 회전을 발동하지 않습니다. 일반 보행의 방향 변화로
측정된 벡터 가속도는 `maxAcceleration`보다 클 수 있습니다.
`excessSpeedHalfLife>0`을 지정하면 이전 tick 속도 중 `maxSpeed` 초과분만 해당 반감기(초)로 감쇠합니다.
새 외력 입력 전에 적용하므로 이번 tick의 밀림을 즉시 약화하지 않습니다. 기본값 0은 감쇠를 끄며,
보행 속도 이하의 동작은 유지됩니다. 강한 밀림 뒤 회복을 조정할 때 TinyDead의 게임 영역 설정인 0.15초를 사용할 수 있습니다.

접촉 예산은 유닛당 **후보 24 / 저장 쌍 8 / 반복 8회**로 고정됩니다. 검색은 가까운 셀부터
시작하고, 자기 이동량과 보정 여유를 포함합니다. 빠른 높은 ID 유닛도 swept pair를 소유할 수 있습니다.
접촉 격자는 셀당 4개 고정 슬롯과 개체별 넘침 연결 목록을 사용합니다. 한 번의 개체 순회로
재구축하며, 셀 방문 순서와 셀 안의 ID 내림차순을 유지합니다. 넘침 개체를 버리지 않으므로
과밀 셀에서도 기존 후보 예산이 선택하는 대상은 같습니다. 격자 버퍼는 셀당 24바이트와
개체 용량당 4바이트를 사용합니다. 이전 연속 배열 방식보다 셀당 약 12바이트를 더 사용해
누적합과 두 번째 위치 순회를 제거합니다. 진단용 `cellStart`·`agentIndices`는 최초 조회 시
연속 배열을 만들며, 이후 재구축에서도 같은 배열을 갱신합니다. 이 진단 뷰를 사용하는 동안은
추가 배열 메모리와 연속 배열 갱신 비용이 발생합니다.
고정된 후보 목록에서 swept-pair 보정은 두 끝점을 순차 변경하고, XPBD 잔여 보정은 배열에 모아
동시 반영합니다. 전체 과정을 병렬 Jacobi로 간주해 그대로 병렬화하면 안 됩니다.
후보를 고르는 동안 위치가 고정되므로 개체별 검색 여유 폭을 한 번 계산하며, 선택된 쌍의 접촉 지름은
8회 반복에서 재사용합니다. 두 캐시는 매 tick 갱신해 반경·간격·입력 속도 변경을 반영합니다.

접촉 수에 따른 보정 완화는 여러 이웃의 합산 반발을 줄입니다. `maximumContactCorrection`은
8회에 걸친 **XPBD 겹침 수리 이동량**의 상한입니다. 이미 움직이는 물체를 멈추는 swept 충돌이나
정적 벽 보정 전체의 변위 상한은 아닙니다. 후보 제한 때문에 모든 접촉 검출과 완전 비침투를 보장하지 않습니다.

정적 BVH·주변 후보 캐시는 장애물 순서를 유지합니다. 빈 영역 인증은 안전한 이동의 빠른 경로이며,
정확한 원/사각형 거리와 swept-circle 검사를 대체하는 근사 충돌은 아닙니다.

순차 정적 투영 후에도 장애물 침투가 남으면, 시작점과 겹친 최대 8개 사각형의 4개 면에서
가장 가까운 유효 탈출점을 찾습니다. 후보는 월드 경계·반경 여유를 만족하고 처음에 겹치지 않은
장애물을 이동 구간에서 침범하지 않아야 합니다. 첫 적분에서 복구한 위치가 접촉 후에도 유효하면
마지막 적분에서 재사용합니다. 정상 위치나 단순 정체에 순간이동을 적용하지 않습니다.
완전히 막힌 영역이나 모든 제한 후보가 차단된 경우에는 복구할 수 없으며, 깊은 초기 침투의
원래 연결 영역·연속 탈출·개체 간 비침투까지 보장하지 않습니다.

### 외력

외력 입력은 위치를 쓰거나 별도 이동 모드를 선택하지 않습니다. impulse는 Δv, acceleration은
`a × dt`, blast는 거리별 선형 감쇠를 속도에 더합니다. 확장 충격파는 유닛별 한 번 적용 마스크를 유지합니다.
영역 외력은 벽의 차폐를 계산하지 않으며, 이후 이동의 벽 충돌은 일반 솔버가 처리합니다.

`proxy`는 움직이는 원형 밀림 도구입니다. 강체 장애물이나 차량과의 양방향 충돌이 아니며,
밀집 군중과 도구의 원이 겹칠 수 있습니다. 이동 입력이 없으면 마지막 위치에서 유지됩니다.
`external.active`는 지속 입력 존재, `direct`와 `stats.affected`는 이번 tick에 직접 속도를 받은 대상을 뜻합니다.
이 값으로 일반 이동 계산을 켜거나 끄지 않습니다. [입력 수명과 제한](native-porting.md#외력-입력)을 확인하세요.

지속적으로 관측하는 물체에는 기록을 쌓지 않는 `external.setKinematicProxies()`를 사용할 수 있습니다.
같은 원형 밀기 수식을 사용하며, 직접 접촉한 도착 생존자를 다시 활성화합니다. 고정 배열의 presence
마스크는 호스트가 제공하고 제거 슬롯은 active도 0으로 유지해야 합니다. API의 교체·수명 계약은
[연속 원형 밀기](native-porting.md#연속-원형-밀기)에 있습니다.

## 기능 범위와 알려진 한계

- 과거 통로 안내는 정확한 최단 경로가 아니며 폭을 유지하는 만큼 이동 거리가 늘어날 수 있습니다. 전역 분할선 때문에 복잡한 지형에서는
  구간이 작아질 수 있고, 셀 전체가 들어가지 않는 좁은 길은 기존 격자로 통과합니다. 통과 용량이나 대형 유지의 보장은 없습니다.
  같은 통로로 합류하는 별도 군중의 좌우 위치는 겹칠 수 있으며, 이때 기존 압력·접촉 솔버가 처리합니다.
- 평면상의 원과 축 정렬 사각형을 처리합니다. 경사·높이·다층·회전 메시 충돌은 없습니다.
- 초기 흐름별 점 목표, 공통 점 목표 변경과 공통 목적지 영역 집합을 지원합니다. 런타임 생성·삭제·배열 재정렬·개별 목표 명령은 없습니다.
- 도착 반경 안에서는 `active=0`이 되어 충돌에서도 빠집니다. 목적지에서 정지 유닛의 공간을 유지하는 정책은 별도 확장입니다.
- 밀집 압축은 여러 tick에 남을 수 있습니다. 전역 침투 0.5px 이하나 운동에너지 단조 감소를 보장하지 않습니다.
- 압력은 밀도 용량 근사입니다. 정확한 원 패킹, 임의 크기 공동 회복, 격자 해상도 독립성을 보장하지 않습니다.
- Float64 CPU 재현성이 다른 언어의 float32·GPU·네트워크 lockstep의 비트 일치를 뜻하지 않습니다.
- 수만 유닛의 전체 게임 프레임 성능은 검증된 계약이 아닙니다. 렌더 FPS와 시뮬레이션 처리량을 분리해 측정합니다.
- 영역 경로 비용은 격자 근사이며 연속 공간의 정확한 최단 거리나 출구 간 균등 이용을 보장하지 않습니다.
  목표 구역 자체는 장애물이 아니며, 구역 경계가 유닛 반경만큼 안쪽으로 축소되는 것은 아닙니다.
