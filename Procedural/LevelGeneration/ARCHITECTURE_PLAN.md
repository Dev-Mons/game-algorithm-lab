# 후속 마일스톤: Surface Region / Facade

상태: 구현·검증 완료 (2026-09-16). 아래 사례와 정책을 먼저 고정한 뒤 구현했다.

목적은 기본 부피를 읽을 수 있는 건물 외관으로 발전시키는 것이다. 기존 `shell-v1` 입력/Golden을 보존하고, 명시적인 `architecture-v1` + `village` 스타일로 새로운 해석을 도입한다.

## 구현 전 고정한 사례와 기대

| 사례 | 기대 해석 |
| --- | --- |
| 높은 본동 3×4×3 + 낮은 별동 4×2×3 | 낮은 직사각형 상면 12면은 하나의 별동 지붕. 본동에 접한 한 변 외의 세 변은 열린 경계다. |
| 6×2×5 기단 위 3×2×3 상부 | 상부를 여러 방향으로 둘러싼 낮은 상면 21면은 하나의 테라스 영역. |
| 한 셀 폭의 단차 | 좁은 선반형 상면은 테라스 유지. |
| 위에 돌출부가 있는 낮은 상면 | 하늘이 일부라도 가려진 영역은 covered-terrace. |
| 분리된 두 건물, 음수 좌표, 순서 교란 | 영역/역할은 각 성분 안에서 결정. 정확한 외피 coverage, 순서 결정론 유지. |
| 모서리/점 접촉 | 비다양체 진단 유지. 해당 입력에서는 새로운 건축 추론을 보류하고 기본 면 덮기를 사용. |
| 직육면체 건물의 외벽 | 같은 평면의 연결 면을 파사드로 그룹화. 성분 최하단에 출입구 한 개, 나머지 적합한 면에 창문. 각 열의 상단은 상단 띠. |
| 돌출부 | 높은 하부면에 문을 만들지 않으며 모든 underside를 보존. |

## 명시적 정책

Region은 같은 성분·방향·평면에서 변을 공유하는 외부 Face의 최대 연결 집합이다. ID는 가장 작은 Face ID를 사용하고 목록은 기존 Face 순서에서 처음 등장하는 순서다. 꼭짓점 접촉은 연결이 아니다.

새 상면 정책은 최고 높이 상면을 roof로 유지한다. 낮은 상면이 직사각형이고 두 수평 길이가 각각 2 이상이며, 한 변 전체에만 높은 점유 벽이 있고 하늘이 가려지지 않았다면 annex-roof다. 그 외는 terrace, 위쪽 점유가 있으면 covered-terrace다. 이 규칙은 기하학적 시각 해석이다. 동일 형태의 실제 옥상 테라스와 별동 지붕을 자동으로 구별할 수 있다고 주장하지 않는다. 수동 면 태그는 요구하지 않는다.

출입구는 성분 최하단의 가장 긴 연속 외벽 줄 가운데에 하나를 고른다. 동률은 PZ/PX/NZ/NX, Region/Face 정규 순서로 해결한다. 외부와 연결된 빈 공간을 향한 출입구이며 실제 지면이나 보행 접근성을 의미하지 않는다. 모서리 진단이 있는 입력은 출입구·창문 해석을 생략한다.

건물 색은 Seed와 성분 ID로 결정하고, 동일 성분의 모든 파사드가 공유한다. Tile/asset/palette 선택은 Core 결과로 고정하며 Renderer는 이를 표시한다. 새 모듈은 공통 unit panel과 공유된 고정 벡터 도안을 재사용한다. 두께 0, face-center, unit-face coverage를 유지하고, 창문/문 도안은 구조 Tile 내부에 그린다. 실제 구멍·별도 겹침 Mesh·임의 epsilon·Voxel별 최종 Mesh는 추가하지 않는다.

## 완료 증거

- 위 사례에 대한 정확한 Region 소속·역할·문/창문 위치, Transform/coverage 및 결정론 테스트
- 기존 v1 Golden 10개 변경 없이 통과, 새 v2 round-trip/Golden/버전 불일치 거부
- 건축 스타일의 공유 모듈 렌더, 영역 선택/경계 비교, 파사드 Trace, 스타일 전환과 저장 재현의 브라우저 검증
- 기존/새 알고리즘의 동일 대표 입력 CPU p50/p95 비교 기록
- 실제 입체 에셋·도로/필지·지형·복잡한 지붕·Godot는 이 마일스톤 뒤의 과제

## 검증 결과

- `tests/architecture.test.ts`: 새 마일스톤의 12건 통과. 기존 테스트를 합하면 `npm run verify`에서 48건과 Application/Core 타입 검사, production build 통과.
- `fixtures/golden-v2/{annex,facade,terrace}.json`: 새 버전의 입력/영역/전체 Trace 고정. 기존 v1 Golden 10개는 수정하지 않았다.
- `e2e/architecture.spec.ts`: 영역/역할 비교, 여러 Material 배치의 실제 화면 클릭 선택, Seed, v2 저장·복원, v1 파일 재생성 통과. 기존 편집 흐름까지 E2E 총 3건 통과.
- 실제 Viewer에서 9개 건물의 외관, 파사드 창문·출입구·상단 띠, 지붕 도안을 확인했다. 면과 영역 Inspector에 Core 선택 결과가 표시된다.
- `npm run measure`: 14개 입력 × reference/village 2개 스타일 × 준비 10회/측정 50회 완료. 마을 건축 최대 CPU p95 22.2ms, 마을 블록 12.7ms. [기록](benchmarks/README.md).
- 공유 unit panel의 정수 Transform과 외피 면 집합은 두 스타일에서 동일하다. 기본 Catalog/Rule과 v1 저장 문서의 의미를 변경하지 않았다. 혼합된 분석/선택 정책은 오류로 거부한다.
