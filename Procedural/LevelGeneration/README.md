# Form & Field — 환경 계획 기반 레벨 생성

건물 부피·도로·인도·오브젝트 의도·지상 주차 영역을 편집하면 공통 공간·접근 계획으로
외벽·출입구·주차 구획·시설물을 생성합니다. 작업 디렉터리는 `Procedural/LevelGeneration`입니다.

## 실행

```sh
npm install
npm run dev
```

| 명령 | 용도 |
|---|---|
| `npm run verify` | 타입·단위 테스트·프로덕션 빌드 |
| `npm run test:e2e` | 실제 브라우저 회귀(성능 측정 제외) |
| `npm run build` | 프로덕션 빌드 |
| `npm run port:export` | 기존 보존 기준을 검사하고 새 네이티브 참조 번들 생성 |
| `npx playwright test e2e/environment.spec.ts --grep '@measure'` | 별도 환경 성능 측정 |

## 편집과 확인

- 건물·인도·도로·주차장/차고·오브젝트 모드를 선택합니다. 왼쪽 클릭/드래그로 영역을 선택하면
  마지막 블록 면 중앙에 정사각뿔 핸들이 나타납니다. 핸들의 밑면 한 변과 높이는 각각 블록 절반입니다.
- 핸들을 면 바깥쪽으로 드래그하면 추가, 안쪽이면 제거합니다. 상부 시점에서는 위/아래 드래그로 추가/제거합니다.
  **E/Q**는 한 층 추가/제거, **Esc**는 선택 해제입니다. 한 칸 이동마다 유효 층을 반영합니다.
- 원본 입력과 공통 Inspector에서 단계·예약·지지·접근 경로·후보 선택/탈락 이유를 확인합니다.
  생성되지 않은 시설도 의도 영역을 선택할 수 있습니다.
- 건물을 선택하면 평평한 면의 내부 격자선을 제외한 외곽선이 표시됩니다.
  A~D의 **외벽 타일 설정**에서 저층·코너·중앙·상층을 A~D 또는 솔리드 벽으로 바꿀 수 있습니다.
  설정은 건물별로 JSON·Undo/Redo·부피 편집에 유지됩니다.
- 세부 용도·수직 비율·건물별 Seed/프로그램/재료/기둥·환경 파라미터 편집 UI는 제공하지 않습니다.
  외벽 시설 종류도 자동 판별하며, 기존 JSON의 명시 종류는 호환 경로로 읽습니다.
- **Ctrl+Z / Ctrl+Shift+Z**는 Undo/Redo입니다. JSON 저장·복원이 가능하며 잘못된 입력/계약 오류는
  마지막 수락 문서와 화면을 유지합니다. 지지가 사라진 오브젝트 입력은 진단과 함께 남습니다.
- 오른쪽 드래그로 카메라 회전, 가운데 드래그로 이동, 휠로 확대합니다. 뷰어 포커스에서 W/S는 전후,
  A/D는 카메라 기준 좌우 이동입니다. 입력창 편집 중에는 카메라가 움직이지 않습니다.
  표시 지면·분석 레이어·카메라는 생성 입력을 바꾸지 않습니다.

## 컨셉과 예제

컨셉은 **A~D 4종과 집 4종**입니다. 컨셉은 외벽 패턴을 바꾸고, 시작 형태 예제는 편집 가능한 부피와
도로·설비 입력을 불러옵니다. 컨셉 선택으로 사용자 부피를 자동으로 깎거나 높이를 바꾸지 않습니다.

| 컨셉 | 외형 | 시작 형태 |
|---|---|---|
| A | 밝은 수평 띠와 어두운 연속 창 | 수평 띠 트윈 타워 |
| B | 브론즈 커튼월·흰 벨트/코너 기둥·어두운 평지붕 | 브론즈 커튼월 오피스 |
| C | 콘크리트 띠·연속창·사선 외장 모서리·높은 저층 창 | 저층/고층과 옥탑, 계단형 매스 |
| D | 흰 외장·반복 창·얇은 슬래브·독립 지상 창 | Tower11 화이트 스텝 타워 |
| 집 | 크림 사이딩·붉은 사이딩·벽돌/기와·차고 | 집 1~6 · Blender 모듈 예제 |

**입면** 카메라로 정면 비례를 비교합니다. **A~D · 도시 컨셉** 예제에는 도로·옥탑·옥상 설비가 포함됩니다.
D 예제의 10×10 → 8×8 → 6×6, 15층+7층+7층은 Tower11의 격자 근사이며 모든 건물에 강제하는 규칙이 아닙니다.

집 예제는 Blender `residential_construction_3m_quarter_optimized.blend`에서 추출한 실제 메시·UV·512px 아틀라스를 사용합니다.
집 1~4는 교차/모임 지붕, 집 5~6은 열린/닫힌 차고 외피입니다. 집 컨셉을 고르면 새 부피에도 모듈을 조립합니다.
집에는 A~D용 타일 교체 UI가 없으며, 필수 외피만 생성합니다. 베란다·현관 계단/차양·굴뚝·배수관·카포트·정원·차량은 자동 복사하지 않습니다.
실내 이동·차고 차량 진입·문 애니메이션은 제공하지 않습니다.

집에 차고를 붙이려면 **주차장·차고 설치**에서 지상 외벽에 붙은 1×2 또는 2×2 직사각형을 선택하고 **E**를 누릅니다.
시작 형태 **집 · 주차 영역으로 붙인 차고**에서도 확인할 수 있습니다. 차고는 주차 영역이 소유하므로 해당 영역을 Q로 삭제하면
집의 공유 벽도 복원됩니다. 부적합 입력의 원인은 Inspector에서 확인합니다. 차고는 검증 완료 주차 대수에 합산하지 않습니다.

## 코드와 이식

- `src/core/environment-generation.ts`: 공통 실행·단계 상태, `rule-spatial-*`·`reservations.ts`: 사전 공간/예약.
- `analysis.ts`·`scene-relations.ts`·`access-graph.ts`: 외피·실제 지지·관계·접근.
- `vertical-design.ts`·`facade-*`·`complete-face-assets.ts`: 수직·입면·마감·완성형 면.
- `roads.ts`·`sidewalks.ts`·`parking-*`·`vehicle-motion.ts`: 도로/인도와 지상 주차 증명.
- `fixture-plan.ts`·`fixture-catalog.ts`: 문맥 시설. `residential-kit.ts`·`attached-garages.ts`: 집/차고.
- `src/environment-editor.ts`·`plan-inspector.ts`·`viewer.ts`: 편집·선택·표시.

다른 엔진에서는 기본 언어로 규칙을 재구현하고 엔진 고유 메시·재질·선택 API를 사용합니다.
원본 TS/Three.js 실행 브리지는 도입하지 않으며 대상은 원본 프로젝트 없이 자체 빌드·실행되어야 합니다.
`port:export`의 214개 A~D 입력/419메시 참조 번들은 집 메시·텍스처까지 포함하지 않습니다.
집의 고정 자료는 `src/assets/residential/{kit.json,meshes.json}`이며 연결된 Blender에서
`tools/blender/export_residential.py`로 재추출합니다. 웹 실행에는 Blender나 원본 Art 프로젝트가 필요하지 않습니다.
