# Form & Field — 절차적 도시 생성 도구

[개발 계획](DEVELOPMENT_PLAN.md)의 구현 대상과 후속 확장을 완료했다. Voxel 부피에서 외피·영역·파사드를 분석하여 공유 모듈을 배치하고, 입체 지붕·창문 프레임·모서리·처마를 생성한다. Seed 기반 도시 부피 생성, 표면 드래그 편집과 Undo/Redo를 제공한다. 데이터 기반 **상가형/업무형**은 지상층·반복층·최상층, 정면 출입구, 기둥과 한 칸 좌/우 조각으로 연결되는 창문을 구성한다. [건축 스타일 규칙과 검증](BUILDING_STYLE_PLAN.md)에 공식 발표의 참고 개념과 프로젝트 고유 정책을 구분했다. [항목별 완료 감사](COMPLETION_PLAN.md)에 구현과 검증 근거를 연결했다.

## 실행

Node.js 22.22.0에서 검증했다. 명령은 이 프로젝트 디렉터리에서 실행한다.

```powershell
cd E:\Project\game-algorithm-lab\Procedural\LevelGeneration
npm ci
npm run dev
```

터미널의 로컬 주소를 연다. 의존성 버전은 package.json/lockfile에 고정되어 있다.

## 사용

1. **시작 형태**에서 기존 예제를 고르거나 **도시 부피 생성**을 펼친다. 블록 수(1~4), 필지 폭(3~6), 도로 간격(1~4), 최대 높이(1~8), 밀도(0~100%)와 격자/중앙 광장 배치를 설정하고 현재 Seed로 생성한다. 전체 수평 범위가 32셀을 넘으면 거부한다. 도로는 건물 사이의 빈 공간이며 지형/노면 Mesh를 생성하는 기능은 아니다.
2. **건축 스타일**에서 새 **상가형/업무형** 또는 입체 우진각·박공·평지붕 또는 이전 버전의 평면 스타일을 선택한다. Seed 변경은 건물별 색상을 바꾼다. 부피 배치를 다시 만들려면 도시 생성 버튼을 누른다. **Style gallery · 1층/2층/본동·별동** 예제에서 높이별 외관을 비교할 수 있다.
3. **왼쪽 드래그**로 표면의 사각 영역을 잡고 버튼을 놓으면 한 층 추가한다. **오른쪽 드래그**는 한 층 제거한다. 빈 바닥에서도 왼쪽 드래그로 시작할 수 있다. 드래그하는 동안에는 선택만 표시하며 부피는 바뀌지 않는다.
4. 편집 후 선택 표시는 이동한 표면에 유지된다. **좌클릭은 한 층 추가, 우클릭은 한 층 제거**하며 번갈아 클릭할 수 있다. **Esc로 선택을 해제**하면 단순 클릭은 부피를 바꾸지 않는다. 다른 영역을 드래그하면 선택을 교체한다. 마지막 층을 지워도 가상 선택면을 유지해 다음 좌클릭으로 복원할 수 있다. 초기 선택은 드래그 시작 면과 같은 평면의 노출 셀로 제한한다. 다른 블록과 겹치는 추가나 빈 셀이 섞인 제거는 전체 작업을 거부하고 선택을 이동하지 않는다.
5. 키보드 **실행 취소 / 다시 실행**으로 부피, Seed, 스타일과 불러오기를 되돌린다. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl+Y를 지원한다. 입력 필드에서는 브라우저의 텍스트 편집 단축키를 유지한다. 이력은 최대 64개 및 이전 상태 문자열 약 8 MiB로 제한한다. 실패한 편집은 이력을 추가하거나 Redo 분기를 지우지 않는다.
6. **가운데 버튼 드래그는 회전, Shift+가운데 드래그는 이동, 휠은 확대/축소**다. **표시 레이어 · 분석**을 펼쳐 원본 Voxel, 분석 표면, 모듈, Edge, 법선, 선택 영역을 독립 비교한다. **하부 카메라**로 바닥과 돌출부 하단을 확인한다. 표시용 지면/높이/카메라는 Core의 배치를 바꾸지 않는다.
7. 편집 영역이 없는 상태에서 면 또는 부착 모듈을 클릭하거나 **표면 분석 · 생성 근거**를 펼쳐 Inspector 목록에서 고른다. Inspector 선택은 블록 편집 영역을 만들지 않는다. Tile/Module, Rule, coverage 수, Palette, 영역 해석, 처마의 빈 공간 확인 위치와 전체 Trace를 볼 수 있다.
8. **JSON 저장 / 불러오기**는 완성된 Grid 전체와 Seed·Catalog·Rule·Style·정책 버전을 보존한다. 도시 생성 폼과 카메라는 편집 UI 상태이며 저장된 Grid의 재생성에 필요하지 않다. Ctrl/Cmd+S로 저장할 수 있다. 새로고침 전 파일을 저장해야 한다.

드래그 범위 초과나 편집 상한 초과는 마지막 부피·선택·이력을 보존하고 안내한다. 파일/설정 검증이나 생성 실패 시 이전 장면을 비우고 `ERROR`를 표시하며 저장을 비활성화한다. **현재 입력 다시 생성**으로 마지막으로 수락한 입력을 다시 표시할 수 있다. `DEGRADED`는 모서리/점 접촉 등 지원하지 않는 경계가 있다는 뜻이며, 기본 면 덮기를 유지하고 고급 건축 추론을 보류한다.

Core는 DOM·Three.js·시계·파일 I/O에 의존하지 않으며 별도 타입 설정으로 검사한다. 공유면과 밀폐 공동에는 구조물을 배치하지 않는다. 바닥과 외부 돌출 하부면은 항상 유지한다. 빈 입력은 정상이고 중복 Cell은 집합으로 정규화한다. 좌표 절댓값은 1,000,000 이하, 점유 범위는 축별 32셀 이하다.

모서리 모듈은 기존 두 Wall의 소유권을 제거한 뒤 대체한다. 입체 지붕은 해당 상면 집합을 통째로 대체한다. 처마는 `attachment`이며 구조 coverage는 비어 있다. 구조 모듈과 단위 패널을 합쳐 모든 외피의 소유자가 정확히 하나인지 검사한다. 프레임/처마는 최대 1/8 unit 돌출이고 Mesh는 Asset 종류별로 공유한다. Voxel마다 최종 Mesh를 생성하지 않는다.

## 지원 범위와 조건부 항목

입체 지붕은 위가 열려 있고 높은 인접 벽이 없는 직사각형 roof Region에 배치한다. 붙어 있는 별동이나 오목한 지붕은 해당 스타일의 평면 지붕을 유지하고 이유를 Trace에 남긴다. 모든 형태의 박공/곡면/아치를 해결하는 시스템은 아니다. 창문·출입구는 외피 도안과 돌출 프레임이며 내부 공간이나 실제 통로를 만들지 않는다.

Incremental/Worker/WASM/GPU 최적화는 원 계획의 측정 조건이 충족되지 않아 도입하지 않았다. 지형, 실내, 범용 Plugin/Rule DSL, Godot 실행은 명시적 제외다. 이들은 미완료된 필수 기능으로 숨기지 않고 [완료 감사](COMPLETION_PLAN.md)의 별도 범위 표에 기록했다. Miniopolis의 내부 구현이나 완제품 전체를 재현했다고 주장하지 않는다.


## 새 건축 규칙의 정책과 한계

공식 발표에서 참고한 개념은 BDF의 층 구성 → 층별 모듈 세트 → 가로 문법/길이 평가다. 사용자가 제공한 [공식 발표 타임코드](https://www.youtube.com/watch?v=usJrcwN6T4I&t=1599s)와 이번 프로젝트 정책의 차이는 [BUILDING_STYLE_PLAN](BUILDING_STYLE_PLAN.md)에 기록했다. 원본 BDF 전체 문법이나 City Sample 스타일의 복제품은 아니다.

이 프로젝트는 Grid를 늘이지 않고 정수 한 칸 단위로 배치한다. 창문 두 조각은 함께 결정하고 맞닿는 세로 프레임 없이 각각 instancing한다. 실제 연속 구간만 채우며, 짧은 구간은 단독 창/벽으로 대체한다. 반복층은 같은 Region의 패턴과 기준 열을 공유한다. 기존 모서리 대체는 새 스타일 면을 건드리지 않으며, 상단 장식은 coverage 없는 부착물이다.

지면은 문서 Y=0으로 명시한다. 성분 최하단이 Y=0이고 해당 셀 아래가 비어 있어야 출입구 후보가 된다. 가장 긴 접지 구간 하나만 정면 입구를 가진다. 떠 있는 부피, 표시 지면 슬라이더와 실제 도로 접근성은 이 판정을 바꾸지 않는다. 로컬 상단 경계는 전체 층 역할과 별개이므로 낮은 별동/테라스에도 마감이 붙는다.

지원은 축 정렬, 단위 층 높이, 구조화 데이터의 start/repeat/end 패턴, single/left/right 창문까지다. 가운데 조각 역할은 데이터 계약에만 있고 에셋은 아직 없다. 임의 층고·곡면·stretching·문자열 DSL·실내는 제외하며, 비다양체 부피는 기본 벽으로 내려간다. 이번 변경의 성능 benchmark는 별도로 수행하지 않았다.


### 대칭 벽면 패턴 — 스타일 v2

새로 선택하는 상가형·업무형은 양 끝 마감/기둥(X)과 중앙 창문(O)을 구분한다. 폭 3 이상 직선 반복층에서 짝수 폭은 `XOOX`, `XOOOOX`, `XOOOOOOX`, 홀수 폭은 `XOX`, `XOXOX`, `XOXOXOX`를 우선한다. 두 칸 연결 창문은 중앙의 OO를 개별 좌우 타일로 구성한다. 폭 1~2는 단독/연결 창문으로 단순화하며, 출입구·구멍·단차에서는 실제 구간과 기존 정렬 조건이 우선한다.

**Facade rhythm · XOOOOX / XOXOX** 시작 형태에서 6칸/5칸 건물을 비교할 수 있다. v4 저장 형식은 유지하고 스타일 정의만 버전 2로 올렸다. 기존 스타일 v1 파일은 내장 정의로 이전 결과를 그대로 복원한다. 이전 v4 Golden 2개도 보존했고 새 `golden-v4-style-v2` 2개를 추가했다. 폭 3~10/네 벽 방향/반복층의 기둥·창문 배열과 이전 저장 결과를 회귀 검사한다.


### 짝수 폭 지상층 — 스타일 v3

짝수 정면은 중앙 두 칸에 출입구를 배치하고 좌우 창문 구간을 같은 폭으로 나눈다. 홀수는 중앙 한 칸 출입구를 유지한다. X=기둥/마감, O=창문, D=출입구이며 폭 14의 예는 `XOXOXODDOXOXOX`다. 문은 중앙에 나란히 있는 두 개의 한 칸 모듈이며, 다른 벽면에 입구를 추가하지 않는다. 실제 연속된 접지 구간에만 적용하므로 구멍이나 단차를 건너 입구를 만들지 않는다.

**Even frontage · 14칸 중앙 출입구** 예제로 확인할 수 있다. 스타일 정의의 `entranceLayout: "centered-parity"`가 이 정책을 켠다. 미지정/`single-center`는 이전 단일 입구 배치다. 새 스타일은 v3, 해석기 계약은 schema 4 / `building-patterns-v2`이며, v1/v2 스타일 파일과 이전 Golden은 그대로 보존했다. 새 Golden은 `golden-v4-style-v3`에 있다.

## 건물별 테마 (#12)

편집 영역을 Esc로 해제한 뒤 건물 면/모듈을 클릭하면 연결된 건물 전체를 노란 선으로 표시한다. 선택 건물 테마에서 상가형/업무형을 바꾸며, 부피와 다른 건물의 테마는 유지된다. 빈 공간 클릭 또는 Esc로 해제한다. 전역 스타일과 건물별 override는 별개이며 JSON에는 override의 전체 정의를 저장한다.

병합은 편집 **직전** 건물별 셀 수로 승자를 정한다. 동률이면 각 건물의 최소 셀 좌표를 x/y/z 숫자 순으로 비교한다. 기본 테마 건물도 같은 투표에 참여하며, 분할된 조각은 원본 테마를 승계한다. `buildings.test.ts`와 `e2e/buildings.spec.ts`가 병합·분할·이력·저장 및 클릭 UI를 검증한다.
