# 후속 구현 검증 시나리오

[진입](../VIDEO_RULE_STUDY.md) · [규칙](RULE_SPEC.md) · [보존 계약](CODE_GAP_PLAN.md)

아래는 **앞으로 실행할 인수 시나리오**다. 이번 분석에서 테스트를 실행해 통과했다는 뜻이 아니다. 영상 재현 한 장이 아니라 입력 변형과 음성 사례로 규칙을 검증한다. 작은 도메인에는 고정 반례와 제한된 생성형 사례를 함께 쓰고, 이미 있는 테스트는 확장해서 사용한다. 구현과 같은 분기를 복사한 정답 함수는 만들지 않는다.

## 비교 기준

- 기존 의미 계약: 현재 `semantic-v1` 필드, 진단, 배열 순서, surface/placement/예약/단계 비교. 내부 설명 trace를 확장한 경우 기존 필드 보존과 새 필드를 나눠 보고한다.
- geometry: 실제 mesh bounds, 개구부, 면 소유, 모서리·마감 접합. 픽셀은 카메라/빛을 고정한 보조 자료다.
- 결정론: 캐시 on/off, 반복 실행, 입력 순열에서 완전한 입력이 같을 때 같은 결과.
- 편집 안정성: 원본·의존성이 변하지 않은 칸/면의 의미를 비교. 높이 scope/경로 연결이 바뀐 경우 합법적 전파 범위를 먼저 정의한다.
- 회전·이동: 점유/연결/지지/충돌의 대응 관계를 검증한다. 절대 좌표 해시·방향별 스타일 때문에 모든 색/타일이 회전·이동 전과 완전히 같아야 한다고 요구하지 않는다.

## 조합 검증과 일반화 판정

T03/T04의 형태 × T07의 도로 × T09/T11의 오브젝트를 모두 전수 곱할 필요는 없다. 최소한 다음 독립 조합을 포함한다.

1. L형 낮은 날개+높은 탑, 도로는 오목부 반대편, 옥상 조명 한 칸 삭제.
2. U형 중정, 두 도로 접점 중 하나 제거, 지상 나무와 출입구가 경쟁.
3. 명시 기둥 위 연결부, 그 아래 도로, 비스듬한 카메라와 관계없는 방향의 외벽 시설.
4. 도로 없는 작은 건물+식생+휴식 시설과, 건물 없는 도로+주차만 있는 문서.
5. 높이 scope가 변하는 부피 편집 후 컨셉 교체·Undo/Redo·JSON 복원.

위 조합에 영상 ID/좌표별 분기가 없어야 한다. 동일 실패 조건에는 동일 계열 사유가 나와야 하며, 한 영상의 특이한 배치를 맞추느라 다른 조합의 불변조건을 깨뜨리면 불합격이다.

## 실행할 검사 범위

- **공유 규칙 구현 변경:** 프로젝트 지침에 따라 `npm run verify`(타입·단위 테스트·빌드). 변경한 기능의 의미 있는 T 시나리오를 기존 테스트에 연결한다. `tests/urban-mass.test.ts`, `roads.test.ts`, `fixture-plan.test.ts`, `environment-editor.test.ts`, `concept-preservation.test.ts` 등이 출발점이다.
- **편집/Viewer 변경:** 해당 실제 브라우저 편집·선택·Undo/Redo 사례와 핵심 스크린샷 확인. 기존 `npm run test:e2e` 범위가 변경에 필요하면 실행한다. core 변화만 검증하면서 모든 화면 회귀를 무조건 반복하지 않는다.
- **이식 자료/도구 변경이 추가로 생긴 경우:** `npm run typecheck`, 관련 보존 테스트, `python -m unittest discover -s porting -p 'test_*.py'`, 실제 새 export/verify. 변경하지 않았다면 불필요하게 실행하지 않는다.
- **이번 문서 작업:** 링크·파일·영상 ID/시간·해시·규칙/근거 대응·범위 일관성만 확인한다. 전체 build/test/브라우저 제품 회귀는 수행하지 않는다.

필요 검사가 통과하면 새로운 변경·실패·구체적 미해결 우려가 있을 때만 검증을 확대한다. 성능 합격 임계값은 원본 영상 속도에서 추정하지 않고 현재 프로젝트의 기존 요구 또는 실제 baseline을 사용한다.
