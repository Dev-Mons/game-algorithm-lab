# 도로 규칙 후속 진단

> 이후 사용자 요청으로 [도로 폭·연결·표시 규칙](ROAD_RULES.md)을 개선했다. 아래는 수정 전 반례와 당시의 진단 기록이다.

2026-09-25. 공통 관계 구현 후 사용자 지적에 따라 현재 코드를 직접 실행하고 Chromium의 실제 편집으로 확인했다. 이 문서는 오류 진단이며 도로 알고리즘 수정 완료 보고가 아니다.

## 확인된 오류

1. **직선 도로의 길이가 폭의 배수가 아니면 폭·종류가 바뀐다.** X=0..3, Z=0..7의 폭4×길이8 도로에서 끝 8셀(Z=6,7)을 드래그 선택하고 Q로 제거했다. 입력은 여전히 폭4×길이6 직사각형인데, 출력은 4×4 end 하나 + 2×2 corner 둘이다. 실제 화면에서 직선 차선 끝에 U자형 연결선이 생긴다. 폭3×길이8에서도 끝이 폭2·폭1 코너로 나뉜다.
2. **가짜 교차로가 후속 시설 검증을 오염시킨다.** X=0..4, Z=0..6의 폭5×길이7 직선 도로가 `(2,0,5)`의 `tee`를 생성한다. 조명 의도 `(2,0,7)`은 길이6 도로에서는 배치되지만 길이7에서는 `INTERSECTION_KEEPOUT`으로 전부 탈락한다. 양쪽 모두 실제 분기 없는 직사각형이다. 주차 gate 계획도 동일 tee/cross 판정을 keepout으로 사용하지만 이번 진단에서 실제 주차 수용량 변화까지 측정하지 않았다.
3. **부분 접속을 변 전체의 접속으로 취급해 외곽선이 누락된다.** 폭2×길이5 도로에서 `(1,0,3)` 하나를 제거하면 `(0,0,2)`의 2×1 모듈이 북쪽 port를 가진다. 실제 접속은 왼쪽 한 칸뿐인데 북쪽 변 전체의 edge를 생략하므로 `(1,0,2)` 북쪽의 노출 경계선이 없다. 한 칸 notch의 원본 점유 자체는 보존된다.

## 원인과 영향

[roads.ts](../src/core/roads.ts)의 `analyzeRoads`는 가장 큰 정사각형으로 점유를 먼저 덮고, 그 분할 조각의 이웃 방향을 도로의 연결 형태로 해석한다. 남은 길이의 분할 경계가 진행 방향·폭·교차로 판정에 섞인다. 1×1 잔여 셀만 합치는 보정으로는 2×2 이상 잔여 조각을 처리하지 못한다. `RoadModule.ports`는 방향 이름만 저장하며 접속 구간·폭을 보존하지 않는다. `roadPlacements`는 port가 하나라도 있으면 그 변 전체의 가장자리를 생략한다.

새 관계 인덱스는 이 기존 분석 결과를 재사용했으므로 오류를 해결하지 않았고, 이를 공유하는 시설 설명/keepout에도 잘못된 분류가 전달된다. 오류를 특정 좌표 예외로 고치면 일반적인 길이·폭 변화에서도 같은 문제가 반복된다.

## 이전 검증이 놓친 부분

기존 `tests/roads.test.ts`의 직선은 주로 `길이=폭×5`, 교차로 팔도 폭의 배수다. 새 관계 테스트 역시 폭1/2/4의 정형 십자를 사용했다. 기존 notch 검사는 notch에서 떨어진 모듈과 셀 coverage를 확인하지만 notch의 모든 노출 변을 검사하지 않았다. 따라서 기존 검사 통과는 도로 의미의 충분한 검증이 아니었다. 앞선 완료 판단에서 이 한계를 놓쳤다.

수정 시 필요한 계약은 일정 폭 직선의 임의 길이 보존, 내부 분할선과 실제 도로 분기의 구분, 접속 구간별 port/외곽선, 그리고 실제 교차로만을 사용하는 시설·주차 keepout이다. 폭의 배수가 아닌 길이, 회전·이동, 부분 접속과 폭 변화, 한 칸 편집을 양성/음성 사례로 고정해야 한다. 원본 도로 마스크와 기존 접근/차량 proof는 유지한다.

- Chromium에서 4×8을 실제 드래그/Q로 4×6으로 편집. 원본 도로 24셀, corner 두 개, 브라우저 pageerror 없음: [브라우저 기록](road-rule-evidence/browser-report.json).
- [편집 전](road-rule-evidence/straight-4x8-before.png), [편집 후 잘못된 코너 표시](road-rule-evidence/straight-4x6-after-edit.png), [notch 외곽선 누락](road-rule-evidence/notch-boundary.png)을 직접 확인했다.
