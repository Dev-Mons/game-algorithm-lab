## 적용 결과

- 상가형: 석재 창턱과 인방의 단차, 창호 금속 테두리, 기둥 줄눈과 기둥 머리, 상부 치형 장식.
- 업무형: 더 넓은 창 개구부, 가는 기둥, 돌출 수직 핀, 창 사이 금속 패널.
- 도시형 복합 상가: 전용 16개 프레임 모듈. 2층 그룹 안쪽에서 유리가 U/V 방향으로 연결되며 외곽은 두꺼운 테라코타 프레임.
- 도시형 업무: 별도 16개 프레임 모듈. 같은 연결 계약에 가는 금속 프레임과 세로 창살을 적용.
- 도시형 프레임 전면의 모서리는 실제 사면 메쉬로 빛을 받는다. 설비 루버와 옥상 난간의 추가 디테일도 실제 메쉬다.
- 외벽·프레임·유리·금속의 4개 재질 슬롯을 사용한다. 조적 줄눈과 유리 톤, 평지붕 이음 패턴은 고정된 작은 캔버스 텍스처로 생성한다.

메쉬는 기존 Three.js 프로토타입 라이브러리에 구현했다. 생성 단계에서 부피에 맞추어 메쉬를 늘리거나 외부 모델을 내려받지 않는다. 같은 완성 에셋 키는 하나의 공유 geometry를 사용하며 배치된 면 하나당 Mesh 하나를 유지한다.

## 호환성과 범위

카탈로그 5에 스타일별 도시형 프레임 키 32개를 추가했다. 카탈로그 2/3/4 파일은 해당 버전의 메타데이터를 검증한 뒤 5로 읽으며 기존 스타일과 프레임 선택을 보존한다. 기존 키의 상가/업무 메쉬와 재질은 새 외관으로 표시된다.

부조는 기존 2/16셀 외부 경계 안에, 옥상 난간은 기존 높이 12/16 안에 들어간다. 출입구 통행 폭/높이와 연결 창문의 열린 이음부를 유지한다. 건물 생성 정책, 시드 결정성, 편집·Undo/Redo 계약은 변경하지 않는다.

## 확인 방법

`npm run verify`는 타입 검사, 205개 테스트, 프로덕션 빌드를 확인한다. `tests/facade-refresh.test.ts`는 실제 메쉬 정점의 경계, 문 개구부, 모듈당 400개 미만의 삼각형, 두 도시형의 연속 유리와 저장 호환성을 검사한다.

브라우저 회귀는 다음으로 실행한다.

```sh
npm run test:e2e -- e2e/facade-refresh.spec.ts e2e/urban.spec.ts e2e/building-style.spec.ts e2e/rooftop-walls.spec.ts
```

`artifacts/facade-refresh/index.html`에 네 스타일의 실제 화면과 편집 가능한 JSON이 생성된다. 갤러리의 JSON을 편집기에서 불러오거나 기존 건축 스타일 선택 메뉴로 새 메쉬를 사용할 수 있다.

외벽 geometry와 관련 동작을 검증하는 변경이며, 전체 도시 규모의 GPU 성능 벤치마크는 실행하지 않았다.
